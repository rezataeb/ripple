# Hackathon Rules (MLH standard rules — copy of the event rules for reference)

## Key rules for this build
1. All work on the project is done during the hackathon period.
2. Teams can use an idea they had before, but must not re-use code or other project materials.
3. Libraries, frameworks, and open-source code are allowed.
4. Teams stop hacking when time is up; only small bug fixes after that.
5. Code must be public (git repository) and stay public after the event.
6. AI tools are allowed. Teams must list the AI tools they used in the submission and answer questions about them.
7. Demo video: 2 minutes or less, made during the hackathon weekend, public, and it states the hackathon name at the beginning ("Hey, I'm Sam and this is my demo for CorgiHacks.").
8. Do not submit the project to other hackathons. Do not submit a project that includes prior work.

## Judging criteria (weighted equally)
- **Technology:** How technically impressive is the hack? Difficult problem, clever technique, or many components?
- **Design:** User experience and interface quality.
- **Completion:** Does it work? Did the team achieve what it wanted?
- **Learning:** Did the team stretch itself and learn something new?

Not judged: code quality, pitch quality, idea originality, or how well the project solves a problem. Judges reward a working demo of what was built.
